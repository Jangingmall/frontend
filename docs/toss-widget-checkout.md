## 토스 결제창형 연동 (2026-10-01)

실제 주문서는 Figma UI를 유지하고, 결제 버튼에서 서버가 반환한 tossClientKey로 widgets()를 초기화한다. setAmount에 서버 검증 금액을 설정한 뒤 renderPaymentWindow로 별도 토스창을 연다. paymentRequest 이벤트에서 requestPayment를 호출한다.

- 클라이언트 키: 주문서형·결제창형 키(test_gck / live_gck). API 개별 연동 키(ck)는 설정 오류로 안내한다.
- 서버 승인: 위 클라이언트 키와 같은 세트의 시크릿 키(gsk)를 사용해야 한다. 시크릿 키는 프론트에 넣지 않는다.
- 토스창에서 결제수단을 다시 선택해야 한다. 현재 SDK는 결제창을 열 때 TOSSPAY를 직접 지정하는 공개 옵션이 없다.
- 주문서의 카드/실시간 계좌이체/토스페이를 각각 CARD/TRANSFER/TOSSPAY와 대조한다. 다른 수단은 요청을 보내지 않고 창을 닫은 뒤 재선택 안내를 표시한다. 서버에 준비된 수단을 임의 변경하지 않는다.
- 창이 열려 있는 동안 중복 주문을 막고, 취소·요청 실패·화면 이탈 시 창을 정리한다.
- 성공 리다이렉트만으로 결제 완료 처리하지 않는다. 기존 결제 승인 API와 주문 금액 검증 경로를 유지한다.
- 저장된 배송지는 기존 입력란에 채우되 Figma에 없는 추가 선택칸은 표시하지 않는다.

배포 검증: 새 요청의 /api/payments 응답이 gck 클라이언트 키인지 확인하고, 별도 토스창 진입 및 취소 후 재시도를 확인한다. 실제 승인 테스트는 서버의 대응 시크릿 키 반영 이후 수행한다. 로컬 SDK 테스트 대역 통과는 실제 키 유효성·승인 성공을 의미하지 않는다.

공식 문서: https://docs.tosspayments.com/sdk/v2/js/payment-window
