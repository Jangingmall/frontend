## PL-3 종목 다중 필터 (#44)

기준: #43 병합 후 `dev`의 `23f988c`에서 분기한 `feat/product-craft-filter`.

| 기준              | 반영                                                                                                                              |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 필터 `1301:57168` | PL-3 첫 아코디언 제목을 현재 소분류 이름으로 표시하고 2열 종목 칩 배치. 204px 필터 안 8px 패딩·4px 간격으로 칩 92×28px            |
| 선택 상태         | 기존 outline Button에 `border-jade-fill`, `states-hover` 토큰 적용. 옅은 배경·진한 테두리·다크 텍스트, `aria-pressed`로 상태 전달 |
| 설명 `1301:58952` | 복수 선택·해제 시 전체 페이지 이동 없이 결과만 갱신. 초기화에서 종목·소재·가격·포장 조건 해제, 기존 품절 제외 초기화 유지         |

- 선택 상태는 URL의 반복 `subcategory`를 기준으로 한다. 예: `/products?category=kitchen-1&subcategory=1&subcategory=2`.
- 종목끼리는 OR, 종목과 쓰임 분류·소재·가격·포장·품절 조건은 AND로 적용한다. 선택 순서와 중복을 정규화해 동일 조건은 같은 조회 캐시를 사용한다.
- 필터 변경은 1페이지로 복귀한다. 페이지 이동은 종목 선택을 유지하고, 분류 변경은 종목을 해제한다. 초기화는 분류·정렬·검색어를 보존한다.
- 새로고침·직접 URL 진입·뒤로/앞으로 가기에서 선택과 결과를 복원한다. 선택이 있는 URL로 처음 진입하면 종목 아코디언을 열어 표시한다.
- 종목 조회 중에는 로딩 상태, 실패 시 재시도, 빈 선택지에는 안내를 표시한다. 알 수 없는 종목 ID는 MSW에서 빈 결과를 반환하고 필터 초기화로 복구할 수 있다.
- PL-2의 기존 하위 분류 탐색은 유지한다. GNB·메가패널·분류 코드·진입 계약은 수정하지 않는다.

### API 연결 경계

- **종목 필터는 `NEXT_PUBLIC_API_MOCKING=enabled`로 빌드한 MSW 모드에서만 활성화한다.** 실제 API 모드에서는 종목 아코디언을 숨기고 선택지 조회를 비활성화한다. 서버 초기 조회·브라우저 조회·캐시 키에서 `subcategory`를 제외한다.
- 실제 API 모드에서 직접 입력한 URL의 종목도 선택 상태와 SEO 필터로 적용하지 않으며, 다음 URL 갱신 시 제거한다. 공개 환경 변수는 빌드 때 고정되므로 모드를 바꿀 때 다시 빌드한다.
- 선택지는 `GET /api/products/subcategories`의 실제 BE `develop` 응답 `{ subcategoryId: number, categoryId: number, name: string }[]`을 검증하고 FE `{ id: string, name: string }[]`으로 변환한다.
- BE `categoryId`는 공예 대분류다. 현재 목록의 쓰임 분류(`kitchen-1` 등)와 연결하지 않는다. 현재 endpoint가 전체 종목을 반환하므로 모든 PL-3에 동일한 종목 선택지를 제공한다. 쓰임별 선택지 제한은 후속 API 계약이 필요하다.
- BE 목록 컨트롤러는 현재 Pageable만 받고 종목 필터를 처리하지 않는다. 반복 `subcategory` 요청은 MSW 전용 잠정 계약이다. 실제 상품 목록 연동은 기존 PL-2 응답·페이지 계약 차이까지 함께 해결하고, 서버·브라우저 요청의 OR 필터 동작을 검증한 뒤 UI·URL·조회 제한을 함께 해제해야 한다.
- MSW 종목 ID 1~6과 사기장·유기장·목기장·칠장·나전장·죽세장은 개발용 예시다. Figma의 `종목` 자리 표시를 고정 문구로 쓰지 않고 조회 이름을 표시한다.

### 확인 시나리오

1. `/products?category=kitchen-1&sort=price-desc&page=2`에서 다기·찻잔을 열고 사기장·유기장 선택 → 1페이지, 6개 결과, 정렬 유지.
2. 새로고침 후 두 칩 선택 유지 → 사기장 해제(3개) → 뒤로 가기(6개) → 앞으로 가기(3개).
3. 종목 1·2, 도자기, 최대 20만 원, 포장 가능 조합 → 1개 결과. 초기화 → 소분류 16개, 종목·소재·가격·체크 해제.
4. 360px에서 선택·초기화 및 가로 넘침 확인. 키보드 Tab/Space로 선택 가능.
