# 스테이징 실제 API 모드 정리 (2026-09-29)

이슈 #111 / 브랜치 `fix/staging-live-checkout`

보안팀 동적검사에서 실제 API 모드가 미지원 기능을 시연 데이터로 성공 처리하지 않도록 변경한다. 개발용 MSW 모드와 테스트 fixture는 유지한다.

| ---------------------------------------------- | ------------------------------------------------------- |

## 결제·주소 검색 원인과 수정

기존 실제 주문 화면에서 할인 또는 무통장입금을 선택하면 시연 주문 화면으로 전환됐다. 그 화면은 주소 검색 시 임의 주소를 채우고 토스 SDK를 호출하지 않았다. 해당 전환과 직접 시연 주문 URL 접근을 차단했다. 실제 화면의 카카오 주소 검색과 카드·계좌이체·토스페이 SDK 호출은 유지하고 회귀 테스트를 추가했다.

토스 서버 금액 대조, 주문 식별자 확인, 중복 요청 방지, 승인 API 이후 완료 처리도 유지한다. 실제 스테이징에서 키·외부 서비스·인증 상태에 따른 실패까지 재현한 것은 아니며 실제 결제는 실행하지 않았다.

## 요청 경계

실제 API 모드에서 브라우저 MSW와 Node MSW를 시작하지 않는다. 과거 MSW 서비스워커 등록은 정리하고 브라우저·서버 fetcher는 `/api/mock/*` 요청을 네트워크 전에 거부한다. 오래된 시연 로그인 플래그가 있어도 실제 모드에서는 복원하지 않는다.

## 배포 설정

- 빌드 시 `NEXT_PUBLIC_DATA_MODE=api`, `NEXT_PUBLIC_API_MOCKING`은 비움, `API_BASE_URL`은 실제 스테이징 백엔드 origin으로 설정한다.
- 공개 환경 변수는 빌드 시 반영되므로 재빌드가 필요하다.
- 토스 클라이언트 키는 백엔드 결제 준비 API(POST /api/payments)의 tossClientKey 응답에서 공급한다. 현재 결제 화면은 NEXT_PUBLIC_TOSS_CLIENT_KEY로 대체하지 않으므로 응답 키가 비어 있으면 설정 오류를 표시한다. 비밀키를 프론트엔드에 넣지 않는다.
- 토스 SDK와 카카오 주소 검색 외부 서비스가 브라우저에서 로드 가능해야 한다.
- 이번 작업은 소스 수정이며 원격 배포 설정 변경·실제 결제 승인·환불은 포함하지 않는다.

## 검증

- npm run typecheck, npm run lint, npm run format:check 통과.
- npm run test -- --maxWorkers=6: 210 파일, 1,280개 통과.
- 실제 API 모드 npm run build -- --webpack 통과.
- node scripts/verify-api-mode.mjs 통과: 미지원 UI·직접 URL·이전 시연 로그인 플래그 차단, 실제 HTTP 계약 경유 장바구니·주문 폼, 주소 검색 콜백 반영 확인.
- 브라우저 검사에서 /api/mock 요청(브라우저·백엔드), MSW 요청·등록, hydration 오류, 주문 생성·결제 요청 모두 0건.

브라우저 검사는 제어된 백엔드 응답과 주소 검색 SDK 대역을 사용했다. 카드·계좌이체·토스페이 요청 및 금액 불일치 방어는 단위 테스트로 확인했다. 배포된 백엔드·실제 카카오 검색·토스 승인 성공을 검증한 결과가 아니다.
