# 스테이징 실제 API 모드 정리

## 목적과 범위

보안팀 동적검사에서 실제 API 모드가 미지원 기능을 시연 데이터로 성공 처리하지 않도록 한다. 기존 실제 상품·장바구니·주문 API는 유지한다. 개발용 MSW 모드와 테스트 fixture는 유지한다. 실제 결제 승인·환불을 실행하거나 배포 환경·비밀키를 변경하지 않는다.

## 구현 계획

- [x] 공통 요청: API 모드 MSW 시작 제거, 이전 워커 등록 정리, 시연 세션 복원과 /api/mock 요청 차단. 서버·브라우저 경계 테스트.
- [x] 상품: 홈 베스트·기획전 숨김, 소재·공예·선물 포장·인기/판매/찜 정렬 차단, 직접 URL 조건 정규화, preview=1 진입 차단. 재입고·사진 후기·문의 기능 비활성화.
- [x] 계정·장바구니·취소: 네이버 시연 로그인, 옵션 변경 시 시연 전환, 결제 주문 취소 접수 및 사진 첨부 비활성화. 미결제 전체 취소 유지.
- [x] 결제·배송지: 시연 주문 URL과 할인·무통장입금 진입 차단, 토스 결제 준비/SDK 요청 보존, 실제 주소 검색 진입과 오류 처리 검증.
- [x] 검증: 타입·린트·전체 단위 테스트·빌드, API 모드 브라우저 회귀 검사. 실제 토스 승인과 실서버 인증 검증 여부를 구분해 보고.

## 회귀 중점

이전 sessionStorage 시연 플래그, 직접 preview URL, 미지원 필터 URL, 서버 결제 금액 불일치, 주소검색 서비스 로딩 실패를 검증한다. 실제 API 실패를 시연 성공으로 대체하지 않는다.
